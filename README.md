# 튕겨라, 구슬! — 페그 드롭 로그라이크

구슬을 쏘아 페그를 튕기며 데미지를 쌓고, 바닥의 배율 구역을 지나 적에게 꽂아 넣는
브라우저 로그라이크. 10층을 돌파하면 승리한다.

`index.html` 을 브라우저에서 열면 바로 실행된다. 빌드도, 서버도, 외부 라이브러리도 필요 없다.

## 조작

| 입력 | 동작 |
|---|---|
| 마우스 이동 / 드래그 | 조준 |
| 클릭 / 손가락 떼기 | 발사 |
| ← → | 미세 조준 |
| 스페이스 | 발사 |
| 적 카드 클릭 | 공격 대상 변경 |

## 규칙

한 발이 한 턴이다. 구슬이 페그를 맞힐 때마다 데미지가 쌓이고, 구슬이 바닥으로 빠지면
그 지점의 배율(가운데일수록 높다)을 곱해 지정한 적에게 한 번에 들어간다.

적은 **시간이 아니라 내가 쏜 발 수**로 센다. 발사가 하나 끝날 때마다 살아 있는 적의
카운터가 1씩 줄고, 0이 되는 순간 공격한 뒤 제 주기로 되돌아간다. 조준을 오래 해도
안전하다는 뜻이고, 적을 먼저 죽이면 그 적의 공격은 통째로 사라진다. 그래서 **먼저 죽일
적을 고르는 것**이 전략의 핵심이고, 적 카드의 `3발 뒤 ⚔9` 와 `다음 발 ⚔9`(붉게 깜빡인다),
그리고 상단의 "독버섯이 다음 발에 공격한다" 경고가 그 판단 재료다.

| 적 | 주기 | 피해 | 체력 |
|---|---|---|---|
| 박쥐 🦇 | 2발 | 5 | 34 |
| 유령 👻 | 2발 | 12 | 60 |
| 슬라임 🟢 | 3발 | 7 | 55 |
| 늑대 🐺 | 3발 | 11 | 72 |
| 독버섯 🍄 | 4발 | 9 | 62 |
| 돌골렘 🗿 | 4발 | 16 | 110 |
| 왕관 골렘 👑 | 3발 | 26 | 380 |

층이 오를수록 체력과 피해가 함께 오른다(층당 8.5%). 2발마다 12를 때리는 유령이
초반 최대 위협이다.

이 인과를 네 단계로 나눠 전부 화면에 드러낸다. 숫자가 조용히 바뀌기만 하면
튕김과 적 처치가 무슨 관계인지 플레이해도 알 수 없기 때문이다.

1. **튕김** — 맞힌 페그 자리에 `+3` 이 뜬다.
2. **충전** — 구슬이 품은 데미지를 구슬 위에 숫자로 띄우고, 둘레의 고리가 커진다.
3. **배율** — 구슬이 빠진 슬롯이 번쩍이며 `59 × 3 = 177` 계산을 보여준다.
4. **공격** — 그 숫자가 구체가 되어 보드 밖 적 카드까지 날아가 꽂히고, 그때 체력이 깎인다.

상단 한 줄이 지금 어느 단계인지 말해 주고(충전 중 / 피해 / 반격), 적이 반격하면
체력 바가 붉게 흔들린다.

페그는 세 종류다.

- **파란 페그** — 기본. 맞히면 데미지가 쌓이고 꺼진다.
- **주황 페그(크리티컬)** — 맞힌 순간부터 그 발의 남은 히트가 2.5배가 된다.
- **빨간 페그(폭탄)** — 주변 페그를 한꺼번에 터뜨리고, 터진 페그도 전부 데미지로 계산된다.

조준선은 **첫 충돌 지점까지만** 보여 주고, 그때 맞을 페그에 테두리를 그려 준다.
주황·빨강 페그를 첫 타로 맞히는 것이 이 게임의 핵심 실력이다. 그래서 특수 페그는
무작위로 뿌리지 않고, **조준선이 닿을 수 있는 자리에 최소 3개를 배치한다**
(`assignSpecials` / `reachablePegs`). 안쪽 깊숙이 묻혀 버리면 겨냥할 방법이 없어
실력이 개입할 여지가 사라지기 때문이다.

전투에서 이기면 구슬 1장·유물·회복 중 하나를 골라 덱을 키운다.
구슬 9종, 유물 12종, 적 7종이 들어 있다.

## 구조

```
index.html        화면 뼈대
css/style.css     UI 스타일
js/content.js     구슬·유물·적 데이터와 층별 조우 구성
js/physics.js     원-원 충돌만으로 이루어진 최소 물리 엔진
js/audio.js       WebAudio 효과음 (연속 히트마다 음이 반음씩 올라간다)
js/game.js        런/전투 흐름, 보드 생성, 렌더링, 입력
test/             자동 플레이 테스트 (Playwright)
```

물리는 직접 구현했다. 중력으로 가속하고, 페그와는 법선 방향 반사 + 반발계수로 튕기며,
한 프레임을 5번으로 쪼개 터널링을 막는다. 조준선은 이 물리를 그대로 미리 굴려 보는
것이라 화면에 보이는 선과 실제 궤적이 어긋나지 않는다.

**재생 속도**는 `physics.js` 의 `TIME_SCALE` 하나로 조절한다. 속도를 k배 할 때
중력을 k²배 하면 궤적의 모양은 그대로이고 같은 길을 더 느리게 지나가기 때문에,
이 값을 바꿔도 조준선 예측과 밸런스가 어긋나지 않는다. 현재 값은 `0.65`
(원래의 약 1.5배 느리게)이며, 한 발의 길이는 중앙값 4.0초 / 최대 8.5초다.

페그 사이에 끼면 최소 속도를 넣어 밀어내는데, 이 주입이 홈에 자리잡은 공에는
매 충돌마다 힘을 다시 넣어 주는 꼴이 되어 영원히 튕기는 문제가 있었다(실측 최대
100초). 주입을 시간에 따라 0으로 줄이고 그래도 안 끝나면 강제 종료하도록 고쳤다.

## 테스트

게임 로직 그대로 브라우저 안에서 수백 판을 돌려 밸런스를 측정한다.
`window.__peg` 훅이 애니메이션을 기다리지 않고 한 발을 끝까지 굴려 주기 때문에
100런이 몇 초 만에 끝난다.

```bash
npm install          # playwright (테스트에만 필요)
npm run smoke        # 입력 경로 + 30런 완주, 예외/무한루프 검출
npm run balance      # 무작위 조준 vs 특수 페그 조준 비교
```

크로미움이 따로 깔려 있는 환경이면 `PW_CHROMIUM=/경로/chromium` 으로 지정한다.

### 현재 밸런스 (100런 기준)

| 조준 방식 | 승률 | 평균 도달 | 전투당 발사 |
|---|---|---|---|
| 완전 무작위 | 3% | 7.0층 | 4.2발 |
| 특수 페그 조준 | 22% | 8.4층 | 3.7발 |

보상은 양쪽 다 무작위로 골랐으므로, 시너지를 보고 덱을 짜는 사람은 이보다 높게 나온다.
조준만으로 승률이 7배 차이 난다는 것이 이 수치의 요점이다.
